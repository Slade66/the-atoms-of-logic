# Go 如何将同一类型的方法分散到多个文件中

## 一、结论

- **允许分散：** Go 允许把同一类型的方法定义在同一个 `package` 的不同 `.go` 文件中；类型定义与方法定义不必位于同一个文件。

- **组织方式：** 可以按职责拆分文件，例如 `user.go` 放 `User` 的结构定义，`user_validate.go` 放校验逻辑，`user_json.go` 放序列化逻辑。

### 1.1 示例

- **目录结构：** 一个 `account` package 可以由多个源文件共同组成。

    ```text
    account/
    ├── user.go
    ├── user_display.go
    └── user_validate.go
    ```

- **类型与方法：** `User` 的定义、展示方法和校验方法虽然分布在三个文件中，但都属于 `account.User`。

    ```go
    // user.go
    package account

    type User struct {
        Name string
    }

    // user_display.go
    package account

    func (u User) DisplayName() string {
        return u.Name
    }

    // user_validate.go
    package account

    func (u User) Valid() bool {
        return u.Name != ""
    }
    ```

## 二、理解 package 与文件的关系

- **package 是编译单位：** 应把 Go package 理解为“文件夹级的模块”，而不是把单个 `.go` 文件当作独立模块。同一个 package 中、参与本次构建的源文件会被一起处理。

- **文件只是组织单位：** 文件负责让代码按职责保持清晰；它不会把其中的类型、函数或方法限制在当前文件可见的范围内。

- **书籍类比：** `.go` 文件像一本书的不同章节，package 才是整本书。编译器校对的是整本书，而不是读完上一章才能理解下一章。

## 三、编译器如何处理多个文件

### 3.1 不是逐文件依赖编译

- **常见误解：** 编译器不是先完成 `user.go` 的编译，再让 `user_validate.go` 依赖其产物；因此，方法文件不需要排在类型定义文件之后。

### 3.2 先收集，再统一检查

- **第一轮：** 编译器收集本次构建中该 package 的全部声明。

    - 有类型 `User`。

    - 有方法 `User.Valid`。

    - 有函数 `NewUser`。

    - 有变量 `defaultUser`。

- **第二轮：** 编译器在完整的声明集合上进行名称与类型检查。

    - `User.Valid` 的接收者 `User` 是否存在。

    - `NewUser` 返回的 `User` 是否匹配。

    - 调用 `u.Valid()` 时，`User` 是否拥有该方法。

- **检查结果：** 到统一检查阶段，编译器已经同时知道 `User` 定义在 `user.go`、`User.Valid` 定义在 `user_validate.go`；二者属于同一个 package 的同一套声明。
