# Go 表格驱动单元测试：从用例建模到子测试执行

## 一、用例表如何建模

### 1.1 核心结构

- **核心思路：** 表格驱动测试把多组输入和期望结果组织成一个用例切片，再复用同一套测试逻辑逐条验证。每条用例的字段分别对应被测函数的参数和返回值。

    | 字段类别 | 作用 | 常见命名 |
    | --- | --- | --- |
    | 用例名称 | 描述当前场景，便于定位失败。 | `name` |
    | 输入字段 | 对应被测函数的参数。 | `input`、`a`、`b`、`options` |
    | 期望字段 | 对应被测函数的返回值。 | `want`、`wantErr` |

- **字段映射：** 不同函数需要不同的用例结构。

    - `func Add(a, b int) int`：使用 `name`、`a`、`b`、`want`。
    - `func Validate(input string) error`：使用 `name`、`input`、`wantErr`。
    - `func Parse(input string) (Result, error)`：使用 `name`、`input`、`want`、`wantErr`。
    - `func DefaultConfig() Config`：使用 `name`、`want`。
    - `func Contains(values []string, target string) bool`：使用 `name`、`values`、`target`、`want`。
    - `func Split(input string) (left, right string)`：使用 `name`、`input`、`wantLeft`、`wantRight`。

### 1.2 错误期望

- **`wantErr`：** 当函数返回 `error` 时，可用 `wantErr bool` 表示是否预期发生错误。

    - `wantErr == false`：预期 `err == nil`。
    - `wantErr == true`：预期 `err != nil`。

- **错误类别：** `wantErr` 只能判断“有没有错误”；需要判断具体错误类别时，应保存预期错误，并使用 `errors.Is` 比较。

    ```go
    var ErrInvalidInput = errors.New("invalid input")

    func Validate(input string) error {
        if input == "" {
            return fmt.Errorf("validate: %w", ErrInvalidInput)
        }
        return nil
    }

    func TestValidate(t *testing.T) {
        testCases := []struct {
            name    string
            input   string
            wantErr error
        }{
            {
                name:    "空输入",
                input:   "",
                wantErr: ErrInvalidInput,
            },
            {
                name:  "合法输入",
                input: "hello",
            },
        }

        for _, tc := range testCases {
            t.Run(tc.name, func(t *testing.T) {
                err := Validate(tc.input)
                if !errors.Is(err, tc.wantErr) {
                    t.Errorf(
                        "Validate(%q) err=%v, wantErr=%v",
                        tc.input,
                        err,
                        tc.wantErr,
                    )
                }
            })
        }
    }
    ```

    - `wantErr == nil`：预期不返回错误。
    - `wantErr == ErrInvalidInput`：预期错误链中包含 `ErrInvalidInput`。

## 二、用 `t.Run` 执行子测试

### 2.1 表格驱动测试

- **`t.Run`：** `t.Run(name, f)` 以 `name` 为名称运行函数 `f`，把当前用例组织成一个子测试。

- **示例：** `strconv.Atoi` 接收字符串，并返回整数和 `error`，因此用例同时包含 `input`、`want` 和 `wantErr`；测试文件需要导入 `strconv` 和 `testing`。

    ```go
    func TestAtoi(t *testing.T) {
        testCases := []struct {
            name    string
            input   string
            want    int
            wantErr bool
        }{
            {
                name:  "正整数",
                input: "42",
                want:  42,
            },
            {
                name:    "非法字符串",
                input:   "abc",
                wantErr: true,
            },
        }

        for _, tc := range testCases {
            t.Run(tc.name, func(t *testing.T) {
                got, err := strconv.Atoi(tc.input)

                if gotErr := err != nil; gotErr != tc.wantErr {
                    t.Errorf(
                        "Atoi(%q) err=%v, wantErr=%v",
                        tc.input,
                        err,
                        tc.wantErr,
                    )
                    return
                }

                if err == nil && got != tc.want {
                    t.Errorf(
                        "Atoi(%q) got=%d, want=%d",
                        tc.input,
                        got,
                        tc.want,
                    )
                }
            })
        }
    }
    ```

- **名称作用：** 每条用例都会拥有独立名称；例如非法字符串失败时，输出会定位到 `TestAtoi/非法字符串`。

### 2.2 `t.Run` 的返回值

- **返回含义：** 未使用 `t.Parallel` 时，`t.Run` 返回的 `bool` 表示该子测试是否通过。

- **常见用法：** 普通表格驱动测试通常忽略返回值；只有后续步骤依赖前一个子测试成功时，才需要判断它。

    ```go
    func TestWorkflow(t *testing.T) {
        var preparedValue int

        ok := t.Run("准备数据", func(t *testing.T) {
            preparedValue = 42
            if preparedValue == 0 {
                t.Error("准备数据失败")
            }
        })
        if !ok {
            return
        }

        t.Run("使用数据", func(t *testing.T) {
            if preparedValue != 42 {
                t.Errorf("got=%d, want=42", preparedValue)
            }
        })
    }
    ```

## 三、失败信息如何表达

### 3.1 让失败原因一眼可见

- **表达目标：** 测试失败时，读者应当只看错误信息，就能知道测试了什么、实际得到什么、原本期望什么。

- **推荐格式：** 使用 `被测函数(输入) got=实际值, want=期望值`。

    ```text
    Atoi("41") got=41, want=42
    ```

- **错误结果：** 如果实际错误与预期不符，应同时输出 `err` 和 `wantErr`。

    ```text
    Atoi("abc") err=strconv.Atoi: parsing "abc": invalid syntax, wantErr=false
    ```

### 3.2 分别检查错误和值

当函数同时返回结果和 `error` 时，应先判断错误是否符合预期。错误不符合预期时直接结束当前用例，避免继续比较一个可能无效的结果。

```go
got, err := strconv.Atoi(tc.input)

if gotErr := err != nil; gotErr != tc.wantErr {
    t.Errorf(
        "Atoi(%q) err=%v, wantErr=%v",
        tc.input,
        err,
        tc.wantErr,
    )
    return
}

if err == nil && got != tc.want {
    t.Errorf(
        "Atoi(%q) got=%d, want=%d",
        tc.input,
        got,
        tc.want,
    )
}
```

- 第一段判断“是否应该返回错误”。
- `return` 只结束当前子测试，不会阻止其他用例继续执行。
- 只有 `err == nil` 时才比较返回值。

### 3.3 选择合适的格式符

- **`%q`：** 输出带引号和转义符的字符串，适合展示输入，例如 `""`、`" "`、`"\n"`。

- **`%v`：** 按默认格式输出值，常用于 `error`、布尔值和其他通用数据。
