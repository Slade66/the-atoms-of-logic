# Go 项目中 cmd 目录的命名与拆分

## 一、目录命名

- **命名依据：** `cmd/` 下的一级目录应按最终生成的可执行程序命名；一个目录对应一个可独立构建和运行的命令。

### 1.1 目录示例

- **多个命令：** API 服务、后台任务和迁移工具是三个独立程序，因此分别放在三个目录中。

    ```text
    cmd/
    ├── api-server/
    │   └── main.go
    ├── worker/
    │   └── main.go
    └── migrate/
        └── main.go
    ```

- **入口 package：** 每个命令目录中的 `main.go` 都使用 `package main`。

### 1.2 构建方式

- **按命令构建：** 构建时指定对应的命令目录，并为产物指定与命令一致的名字。

    ```bash
    go build -o api-server ./cmd/api-server
    go build -o worker ./cmd/worker
    ```

## 二、何时拆分多个 cmd

- **单一进程：** 即使项目内部包含多个业务模块，只要它们最终运行在同一个单体进程中，就只需要一个 `cmd/<程序名>` 作为入口。

- **独立进程：** 当某部分需要被构建、部署和运行成独立进程时，再为它增加一个新的 `cmd/<程序名>` 目录。

## 三、cmd 的职责边界

- **程序组装：** `cmd/<程序名>` 负责程序入口与依赖组装，例如读取配置、创建依赖和启动程序。

- **保持轻薄：** 不要把大段业务逻辑放进 `cmd/.../main.go`；业务逻辑应放在可被入口调用的其它包中。
