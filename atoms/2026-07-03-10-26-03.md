# Linux 的网卡命名机制

- `ens192`、`ens3`、`enp1s0`、`eth0`，都是 Linux 给“网络接口”起的名字。它们不是网卡自带的名字，而是系统启动时根据硬件信息和命名规则临时分配出来的名字。

## 一、网卡和网络接口

- **网卡：** `NIC`（Network Interface Card，网络接口卡）是机器用来联网的硬件，负责真实收发网络数据的设备。

- **网络接口：** `interface` 是代表这张网卡的名字，是操作系统用来操作网络的入口，是用来配置 IP、路由、收发包的逻辑对象。

- **两者关系：** 网络接口不一定等于实体网卡，它可以对应一块真实网卡，也可以是系统虚拟出来的接口。

    - `eth0`、`ens33`：常见的有线网卡接口名。

    - `lo`：本地回环接口（loopback），是“自己访问自己用的接口”，不是实体网卡。

    - `docker0`：Docker 创建的虚拟网桥（“虚拟交换机一样的东西”）。

    - `vethxxx`：虚拟网卡对（veth pair，大白话就是“两个虚拟接口成对出现，用来连接容器和宿主机”）。

## 二、系统启动时如何发现并命名网卡

- **启动流程：** Linux 先发现硬件，再创建接口名。

    1. 内核（kernel）启动。

    2. 内核扫描硬件位置，比如 PCI/PCIe。

    3. 内核发现一块网卡设备。

    4. 内核加载对应的驱动。

    5. 系统创建一个网络接口。

    6. `udev/systemd` 给这个接口起名。

    7. 网络服务读取 ifcfg 配置文件，把 IP/网关/DNS 配到对应网卡上。

- **命名结果：** 如果系统根据硬件位置判断这张网卡和 slot `192` 有关，就可能把它叫成 `ens192`；如果判断它在某个 PCI 路径上，就可能叫成 `enp1s0`。

## 三、为什么早期叫 eth0，又为什么不好

- **早期命名：** 早期 Linux 的有线网卡通常叫 `eth0`、`eth1`、`eth2`。

    - `eth`：Ethernet（以太网）。

    - `0/1/2`：第几块网卡。

- **核心问题：** `eth0` 的名字容易受“发现顺序”影响，大白话就是“谁先被系统看到，谁就可能叫 `eth0`”。

- **风险场景：** 一台机器有两张网卡时，第一次启动可能是业务网卡先被发现，所以它叫 `eth0`；下次启动如果管理网卡先被发现，管理网卡就可能变成 `eth0`。

- **后果：** 配置文件原本把业务 IP 配在 `eth0`，但重启后 `eth0` 换成另一张网卡，业务 IP 就可能跑到错误网卡上，网络就乱了。

## 四、现代 Linux 为什么改成 ens192 / enp1s0

- **设计目标：** 现代 Linux 引入 predictable network interface names（可预测网卡命名），就是“按硬件位置给网卡起名”，减少顺序变化带来的混乱。

- **常见名字：** 不同前缀代表不同命名依据。

    | 名字 | 大概含义 | 大白话 |
    | --- | --- | --- |
    | `ens192` | slot | 和插槽编号相关的网卡 |
    | `enp1s0` | PCI path | 按 PCI 位置命名的网卡 |
    | `eth0` | fallback | 老式兜底命名 |

- **ens192 拆解：** `ens192` 可以粗略拆成 `en` + `s` + `192`。

    - `en`：Ethernet（以太网）。

    - `s`：slot（插槽）。

    - `192`：插槽编号，或者虚拟平台暴露出来的位置编号。

    - 解释：这是一张以太网卡，Linux 认为它的位置和 slot `192` 有关，所以叫 `ens192`。

- **enp1s0 拆解：** `enp1s0` 可以粗略拆成 `en` + `p1` + `s0`。

    - `en`：Ethernet（以太网）。

    - `p1`：PCI bus 1（PCI 总线 1，“第 1 条硬件通道”）。

    - `s0`：slot 0（插槽 0，“这个通道上的第 0 个位置”）。

    - 解释：这是一张以太网卡，Linux 按它在 PCI 里的位置给它起名。
