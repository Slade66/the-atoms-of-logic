# git pull

## 当本地分支和远端分支分叉导致 `git pull` 失败时

- **`git pull --rebase`：** 先获取远端的新提交，再暂时取下本地独有的新提交，让本地 `main` 先接上远端的新提交；最后按照原来的顺序，把本地的新提交逐个重放到后面。最终形成“远端新提交在前，本地新提交在后”的线性历史。

- **举例：**

    - **分叉时：** 两边从同一点分头提交，历史就分叉了。

        ```text
        origin/main:  76297af ── f9d9150
        本地 main:    76297af ── dd39c8a ── 9088618 ── ec60c8c
        ```

    - **rebase 之后：**

        ```text
        origin/main:  76297af ── f9d9150
        本地 main:    76297af ── f9d9150 ── dd39c8a' ── 9088618' ── ec60c8c' (HEAD)
                                            ▲
                                      你的 3 个提交被重放到后面
        ```

- **为什么 hash 会变：** `rebase` 先让本地 `main` 指向 `f9d9150`，再按原顺序逐个应用本地 3 个提交所记录的改动，并为每次结果创建新的 commit 对象。commit 的 hash 由文件快照、父提交、提交信息等内容共同计算：第一个新 commit 的父提交变成了 `f9d9150`，后两个又分别以刚创建的新 commit 为父提交，因此 3 个 commit 的 hash 都会改变，即使代码改动和提交信息没有变化。
