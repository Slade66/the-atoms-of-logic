# ai-rate-limiting

- **作用：** `ai-rate-limiting` 插件按指定时间窗口内消耗的 token 数量，对发往 LLM 服务的请求做限流，以管理 API 使用、保证资源分配公平，并避免服务过载。

## 限流原理

- **固定窗口：** 窗口内第一次请求打开一个时长为 `time_window` 的桶，这段时间内的 token 都加进这个桶；到期后清零，再开新桶。

- **一次请求的处理顺序：**

    1. **请求时先看已用量：** 已超限则直接 503、不调用模型；未超限则放行，由 `ai-proxy` 调 LLM。

    2. **返回后再记账：** 响应带回 `usage`（prompt / completion / total），log 阶段按 `limit_strategy` 取出本次实际用量，加进计数器。

- **拒的是下一次：** 某次请求把额度用超了，这一次仍会成功；同一窗口内的下一次才会被拒。因为 access 时还不知道这次会花多少。

- **计数位置：** 默认存在本机共享内存。多节点时各算各的，有效额度约等于 `limit × 节点数`。

## 例子

### 一、配合 `ai-proxy` 做限流

> 这个例子演示如何用 `ai-proxy` 转发 LLM 流量，并用 `ai-rate-limiting` 按 token 对该实例限流。

- **适用场景：** 网关后面只有一个模型，要给它封顶。额度用完后直接拒绝，不再调用上游。

1. **创建 APISIX Route：**

    ```bash
    curl "http://127.0.0.1:9180/apisix/admin/routes" -X PUT \
      -H "X-API-KEY: ${admin_key}" \
      -d '{
        "id": "ai-rate-limiting-route",
        "uri": "/anything",
        "plugins": {
          "ai-proxy": {
            "provider": "deepseek",
            "auth": {
              "header": {
                "Authorization": "Bearer '"$DEEPSEEK_API_KEY"'"
              }
            },
            "options": {
              "model": "deepseek-v4-flash"
            }
          },
          "ai-rate-limiting": {
            "limit": 300,
            "time_window": 30,
            "limit_strategy": "prompt_tokens"
          }
        }
      }'
    ```

    - **配置含义：**

        ```text
        Route ID：ai-rate-limiting-route
        外部路径：/anything
        使用插件：ai-proxy、ai-rate-limiting
        目标服务商：DeepSeek
        DeepSeek API Key：从 Authorization 请求头传递
        模型：deepseek-v4-flash
        限流策略：prompt_tokens（只统计输入 token）
        限流额度：30 秒内最多消耗 300 个 prompt tokens
        ```

2. **客户端请求 APISIX：** 请求体带 system prompt 和示例用户问题。

    ```bash
    curl "http://127.0.0.1:9080/anything" -X POST \
      -H "Content-Type: application/json" \
      -d '{
        "messages": [
          { "role": "system", "content": "You are a mathematician" },
          { "role": "user", "content": "What is 1+1?" }
        ]
      }'
    ```

3. **限流效果：** 如果 30 秒内已消耗完 300 个 prompt tokens，后续请求都会被拒绝。

    ```http
    HTTP/1.1 503 Service Temporarily Unavailable
    Date: Fri, 14 Aug 2026 06:20:57 GMT
    Content-Type: text/html; charset=utf-8
    Content-Length: 269
    Connection: keep-alive
    X-AI-RateLimit-Limit-ai-proxy: 300
    X-AI-RateLimit-Remaining-ai-proxy: 0
    X-AI-RateLimit-Reset-ai-proxy: 12
    Server: APISIX/3.13.0

    <html>
    <head><title>503 Service Temporarily Unavailable</title></head>
    <body>
    <center><h1>503 Service Temporarily Unavailable</h1></center>
    <hr><center>openresty</center>
    <p><em>Powered by <a href="https://apisix.apache.org/">APISIX</a>.</em></p></body>
    </html>
    ```

### 二、只限流其中一个实例

> 用 `ai-proxy-multi` 配置两个实例做负载均衡（80% / 20%），只对承担 80% 流量的实例按 token 限流。该实例额度用完后，后续请求转给另一个未限流的实例。

- **适用场景：** 主力模型有预算、备胎不限流。一开始按权重分流；主力打满后，请求全部溢出到备胎，不拒绝。

1. **创建 APISIX Route：** 对 `deepseek-instance-1` 设置 30 秒内 100 个 `total_tokens` 的额度。

    ```bash

      -H "X-API-KEY: ${admin_key}" \
      -d '{
        "id": "ai-rate-limiting-route",
        "uri": "/anything",
        "plugins": {
          "ai-proxy-multi": {
            "instances": [
              {
                "name": "deepseek-instance-1",
                "provider": "deepseek",
                "weight": 8,
                "auth": {
                  "header": {
                    "Authorization": "Bearer '"$DEEPSEEK_API_KEY"'"
                  }
                },
                "options": {
                  "model": "deepseek-v4-flash"
                }
              },
              {
                "name": "deepseek-instance-2",
                "provider": "deepseek",
                "weight": 2,
                "auth": {
                  "header": {
                    "Authorization": "Bearer '"$DEEPSEEK_API_KEY"'"
                  }
                },
                "options": {
                  "model": "deepseek-v4-flash"
                }
              }
            ]
          },
          "ai-rate-limiting": {
            "limit_strategy": "total_tokens",
            "instances": [
              {
                "name": "deepseek-instance-1",
                "limit": 100,
                "time_window": 30
              }
            ]
          }
        }
      }'
    ```

    - **配置含义：**

        ```text
        使用插件：ai-proxy-multi、ai-rate-limiting
        实例 1：deepseek-instance-1，权重 8，模型 deepseek-v4-flash
        实例 2：deepseek-instance-2，权重 2，模型 deepseek-v4-flash
        只限流实例 1：30 秒内最多 100 个 total_tokens
        实例 2：不限流
        ```

2. **客户端请求 APISIX：**

    ```bash
    curl "http://127.0.0.1:9080/anything" -X POST \
      -H "Content-Type: application/json" \
      -d '{
        "messages": [
          { "role": "system", "content": "You are a mathematician" },
          { "role": "user", "content": "What is 1+1?" }
        ]
      }'
    ```

3. **限流效果：** `deepseek-instance-1` 在 30 秒内用完 100 个 token 后，后续请求全部转给未限流的 `deepseek-instance-2`。

### 三、给所有实例同样的额度

> 给 `ai-proxy-multi` 里所有上游实例套同一套限流额度。为便于从响应里区分打到了哪边，一个实例用 OpenAI，一个用 DeepSeek。

    - **配置含义：**

2. **客户端请求 APISIX：** 同一窗口内连发三次。

    ```bash

          { "role": "system", "content": "You are a mathematician" },
          { "role": "user", "content": "Explain Newtons laws" }
    ```

3. **限流效果：**

    2. 第二次转到另一个实例。这次同样超过 100，两个实例额度都用完。

    3. 第三次返回 429：

        ```http
        HTTP/1.1 429 Too Many Requests
        X-AI-RateLimit-Limit-openai-instance: 100
        X-AI-RateLimit-Remaining-openai-instance: 0
        X-AI-RateLimit-Reset-openai-instance: 0
        X-AI-RateLimit-Limit-deepseek-instance: 100
        X-AI-RateLimit-Remaining-deepseek-instance: 0
        X-AI-RateLimit-Reset-deepseek-instance: 0
        ```

### 四、按优先级限流，额度用完后回退

> 两个实例设不同优先级，只对高优先级实例限流。`fallback_strategy` 为 `["rate_limiting"]` 时，高优先级实例额度用完后，请求改走低优先级实例。

- **适用场景：** 质量优先、预算封顶。额度没用完时几乎全走高优先级模型；用完后回退到便宜模型。和例子二不同：二是一开始就按 8:2 随机分，四是额度没用完时优先打高优先级。

1. **创建 APISIX Route：** `openai-instance` 优先级更高，并限制 60 秒内 10 个 `total_tokens`。

    ```bash

      -H "X-API-KEY: ${admin_key}" \
      -d '{
        "id": "ai-rate-limiting-route",
        "uri": "/anything",
        "plugins": {
          "ai-proxy-multi": {
            "fallback_strategy": ["rate_limiting"],
            "instances": [
              {
                "name": "openai-instance",
                "provider": "openai",
                "priority": 1,
                "weight": 0,
                "auth": {
                  "header": {
                    "Authorization": "Bearer '"$OPENAI_API_KEY"'"
                  }
                },
                "options": {
                  "model": "gpt-4o"
                }
              },
              {
                "name": "deepseek-instance",
                "provider": "deepseek",
                "priority": 0,
                "weight": 0,
                "auth": {
                  "header": {
                    "Authorization": "Bearer '"$DEEPSEEK_API_KEY"'"
                  }
                },
                "options": {
                  "model": "deepseek-v4-flash"
                }
              }
            ]
          },
          "ai-rate-limiting": {
            "instances": [
              {
                "name": "openai-instance",
                "limit": 10,
                "time_window": 60
              }
            ],
            "limit_strategy": "total_tokens"
          }
        }
      }'
    ```

    - **配置含义：**

        ```text
        使用插件：ai-proxy-multi、ai-rate-limiting
        回退策略：rate_limiting
        高优先级：openai-instance（priority 1），模型 gpt-4o
        低优先级：deepseek-instance（priority 0），模型 deepseek-v4-flash
        只限流 openai-instance：60 秒内最多 10 个 total_tokens
        ```

2. **客户端请求 APISIX：**

    ```bash
    curl "http://127.0.0.1:9080/anything" -X POST \
      -H "Content-Type: application/json" \
      -d '{
        "messages": [
          { "role": "system", "content": "You are a mathematician" },
          { "role": "user", "content": "What is 1+1?" }
        ]
      }'
    ```

3. **限流效果：**

    1. 第一次走高优先级的 `openai-instance`。这次 `total_tokens` 超过 10，该实例额度用完。

    2. 同一 60 秒窗口内的第二次请求，回退到低优先级的 `deepseek-instance`。

### 五、按 Consumer 限流

> 两个模型做负载均衡，限流规则配在 Consumer 上，而不是 Route 上。不同用户走同一条 Route，各有各的额度。

- **适用场景：** 多租户共用一条模型网关。每个调用方限制不同的模型；某个模型额度用完后，该用户回退到另一个模型。没带密钥的请求直接 401。

1. **创建 Consumer `johndoe`：** 只限制他用 `openai-instance`，60 秒内 10 个 `total_tokens`。

    ```bash
      -d '{

        "plugins": {
          "ai-rate-limiting": {
            "instances": [
              {
                "name": "openai-instance",
                "limit": 10,
                "time_window": 60
              }

            "rejected_code": 429,
            "limit_strategy": "total_tokens"
    ```

### 六、按规则限流

> 用 `rules` 按请求头限流。档位头不能信客户端：先鉴权，由 Go 服务写入 `X-Subscription-ID` / `X-Subscription-Count` / `X-Trial-ID`，网关再按这些头执行规则、调用 LLM。

- **适用场景：** 同一条网关要按订阅、试用等档位给不同额度，且档位必须来自可信的鉴权结果。

- **请求链路：**

    ```text
    用户（只带 apikey）
        ↓
    APISIX 删掉客户端自带的档位头
        ↓
    forward-auth 把 apikey 转给 Go 鉴权服务
        ↓
    Go 校验 apikey，把档位写在响应头里
        ↓
    APISIX 把这些头拷到请求上
        ↓
    ai-rate-limiting 按头执行 rules
        ↓
    ai-proxy 调 LLM
    ```

- **规则怎么跑：** 按数组顺序执行。鉴权写入了 `X-Subscription-ID`，就按订阅 ID 计数，额度取 `X-Subscription-Count`（没有则 500）；写入了 `X-Trial-ID`，就按试用 ID 计数，60 秒 50 token。某条要用的头没有，这条跳过。正式用户和试用用户应由鉴权服务只写其中一套头，不要两套都写。

1. **Go 鉴权服务：** 读 `apikey`（形如 `sk-...`），失败返回非 2xx；成功返回 200，并把档位写在响应头里。客户端不传档位头，传了也不用。

    ```go
    func auth(w http.ResponseWriter, r *http.Request) {
        switch r.Header.Get("apikey") {
        case "sk-paid-example":
            w.Header().Set("X-Subscription-ID", "sub-123456789")
            w.Header().Set("X-Subscription-Count", "500")
            w.WriteHeader(http.StatusOK)
        case "sk-trial-example":
            w.Header().Set("X-Trial-ID", "trial-123456789")
            w.WriteHeader(http.StatusOK)
        default:
            http.Error(w, "unauthorized", http.StatusUnauthorized)
        }
    }
    ```

2. **创建 APISIX Route：** `proxy-rewrite` 优先于 `forward-auth`，先清掉客户端伪造的档位头；`forward-auth` 再向 `http://127.0.0.1:9090/auth` 要可信头。

    ```bash
    curl "http://127.0.0.1:9180/apisix/admin/routes" -X PUT \
      -H "X-API-KEY: ${admin_key}" \
      -d '{
        "id": "ai-rate-limiting-route",
        "uri": "/anything",
        "plugins": {
          "proxy-rewrite": {
            "_meta": {
              "priority": 2010
            },
            "headers": {
              "remove": [
                "X-Subscription-ID",
                "X-Subscription-Count",
                "X-Trial-ID"
              ]
            }
          },
          "forward-auth": {
            "uri": "http://127.0.0.1:9090/auth",
            "ssl_verify": false,
            "request_headers": ["apikey"],
            "upstream_headers": [
              "X-Subscription-ID",
              "X-Subscription-Count",
              "X-Trial-ID"
            ]
          },
          "ai-proxy": {
            "provider": "deepseek",
            "auth": {
              "header": {
                "Authorization": "Bearer '"$DEEPSEEK_API_KEY"'"
              }
            },
            "options": {
              "model": "deepseek-v4-flash"
            }
          },
          "ai-rate-limiting": {
            "rejected_code": 429,
            "rules": [
              {
                "key": "${http_x_subscription_id}",
                "count": "${http_x_subscription_count ?? 500}",
                "time_window": 60
              },
              {
                "key": "${http_x_trial_id}",
                "count": 50,
                "time_window": 60
              }
            ]
          }
        }
      }'
    ```

    - **配置含义：**

        ```text
        客户端只带 apikey（sk-...）
        上游：ai-proxy，DeepSeek deepseek-v4-flash
        proxy-rewrite：删掉客户端自带的档位头（priority 2010，先于 forward-auth 2002）
        forward-auth：把 apikey 交给 Go；把 Go 返回的档位头拷到请求上
        规则 1：按 X-Subscription-ID 计数；额度取 X-Subscription-Count，没有则 500
        规则 2：按 X-Trial-ID 计数；60 秒 50 个 token
        超限状态码：429
        ```

3. **不带 apikey：** 鉴权失败，请求到不了 LLM。

    ```bash
    curl -i "http://127.0.0.1:9080/anything" -X POST \
      -H "Content-Type: application/json" \
      -d '{
        "messages": [
          { "role": "user", "content": "What is 1+1?" }
        ]
      }'
    ```

4. **正式用户：** Go 写入 `X-Subscription-ID` 和 `X-Subscription-Count: 500`，命中规则 1。
