# Nacos：服务发现与配置管理

## 一、Nacos 是什么

- **定义：** Nacos 是微服务系统中的服务注册中心和配置中心。

- **解决的问题：** Nacos 集中管理“服务在哪里”和“服务使用什么配置”，让应用不必把其他服务的地址和运行配置写死在代码中；它只提供服务地址和配置，不处理具体的业务请求。

## 二、Nacos 的作用

### 2.1 服务注册与服务发现

- **示例服务：** 假设系统中有三个 Go 服务。
    ```text
    user-service    → 192.168.1.10:8001
    order-service   → 192.168.1.11:8002
    payment-service → 192.168.1.12:8003
    ```

- **注册流程：** 
    1. 读取 Nacos 地址和自己的监听地址。
    2. 向 Nacos 注册服务名、IP 和端口。
    3. 持续发送心跳，或者由 Nacos 通过健康检查判断实例是否可用。
    4. 服务停止、心跳中断或健康检查失败后，Nacos 将实例标记为不健康或移除。

- **发现流程：**
    1. `order-service` 不以写死的 IP 去找 `user-service`，而以服务名向 Nacos 查询当前有哪些健康实例。
    2. Nacos 返回一个或多个可用实例。
    3. `order-service` 根据负载均衡策略选择实例。
    4. `order-service` 直接调用选中的 `user-service` 地址。

### 2.2 配置管理

- **配置中心价值：** 服务运行时需要的配置从代码和镜像中分离，由 Nacos 集中保存；可以在不重新编译业务代码的情况下调整部分运行参数，并统一管理不同服务的配置。

- **使用流程：** 应用启动时从 Nacos 拉取配置，也可以监听配置变化；管理员修改配置后，应用是否立即生效取决于客户端是否实现了监听和动态刷新。
