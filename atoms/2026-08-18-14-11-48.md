# git stash

- **作用：** 临时把当前没提交的代码修改暂存起来但不提交，让工作区恢复干净。

- **类比：** 你正在桌上用草稿纸写作文，突然要改个设计图。于是把草稿塞进抽屉，让桌面恢复干净，再去处理设计图；处理完打开抽屉，把草稿拿出来继续写。

- **适用场景：** 经常在多个分支之间切换的开发场景。

## 没有 `git stash` 之前，会有什么麻烦？😵

- 当前分支有未提交的代码，你想切换到其它分支时，会提示错误。

- 此时你要么先提交代码，要么先 `git stash` 代码，然后再切换到其它分支。

- 但提交代码有个不好的地方，一旦提交，代码就永远进入 git 历史了，删不掉了... 

## 常用命令

```bash
git stash # 把修改暂存起来。
git stash push -m "开发登录接口" # 给暂存起名字。-m 就是 message（备注信息）。

git stash list # 查看你所有的 stash。

git stash pop # 把暂存的修改恢复到工作区，然后删除暂存。
git stash pop --index # 把代码 + 原来的暂存状态一起恢复。

git stash apply # 把暂存的修改恢复到工作区，但不删除暂存。
git stash apply stash@{1} # 恢复指定编号的暂存。

git stash drop stash@{0} # 删除指定编号的暂存。
git stash clear # 清空所有暂存。
```

## untracked file 不会被 stash

- **默认范围：** `git stash` 只处理已经被 Git 跟踪的文件，不会暂存 untracked file（未跟踪文件，即还没 `git add` 过的新文件）。

- **把新文件也暂存：** `git stash push -u -m "登录功能"`。`-u` 是 `--include-untracked`，把未跟踪的新文件也一起暂存。
