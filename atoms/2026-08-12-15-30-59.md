# APISIX 的 ai-proxy 插件

- **作用：** 用户按照统一的 API 格式请求 APISIX，ai-proxy 插件再将插件配置转换为指定的请求格式，转发到具体平台，简化了对多种模型服务的访问。

- **请求链路：**

    ```text
    用户
    ↓
    APISIX 统一接口
    ↓
    ai-proxy 根据配置适配请求
    ↓
    OpenAI / DeepSeek / VLLM / 其他兼容 OpenAI API 的模型服务
    ```

- **这些服务分为：**
    - 模型厂商： OpenAI、DeepSeek、Anthropic、Gemini。
    - 云平台： Azure、Vertex AI、Amazon Bedrock。
    - 模型聚合平台： OpenRouter。
    - 兼容服务： 只要某个服务提供 OpenAI 兼容接口，也可以接入，例如 VLLM。

## 请求格式

| 名称 | 类型 | 必填 | 描述 |
| --- | --- | --- | --- |
| `messages` | Array | 是 | 消息对象数组。 |
| `messages.role` | String | 是 | 消息角色（`system`、`user`、`assistant`）。 |
| `messages.content` | String | 是 | 消息内容。 |

### 请求示例

```json
{
    "model": "Qwen3-0.6B",
    "messages": [
        {
            "role": "user",
            "content": "请介绍一下模型网关。"
        }
    ],
    "stream": false,
    "max_tokens": 128
}
```

## 插件配置

- `provider`
	- 类型：`string`
	- 必填：是
	- 默认值：无
	- 有效值：
		- `openai`：请求代理到：`https://api.openai.com/chat/completions`
		- `deepseek`：请求代理到：`https://api.deepseek.com/chat/completions`
		- `azure-openai`：按 Azure OpenAI 服务配置转发
		- `aimlapi`：使用 OpenAI 兼容驱动，默认代理到：`https://api.aimlapi.com/v1/chat/completions`
		- `anthropic`：默认代理到：`https://api.anthropic.com/v1/chat/completions`
		- `openrouter`：使用 OpenAI 兼容驱动，默认代理到：`https://openrouter.ai/api/v1/chat/completions`
		- `gemini`：使用 OpenAI 兼容驱动，默认代理到：`https://generativelanguage.googleapis.com/v1beta/openai/chat/completions`
		- `vertex-ai`：默认代理到：`https://aiplatform.googleapis.com`；需要配置 `provider_conf` 或 `override`
		- `bedrock`：代理到 AWS Bedrock Converse API：`https://bedrock-runtime.<region>.amazonaws.com`；使用 AWS SigV4 对请求签名
		- `openai-compatible`：代理到 `override` 中配置的自定义端点

## 其它

- **日志：** 此外，该插件还支持将 LLM 请求信息记录到访问日志（access log）中，例如 Token 用量、模型名称、首次响应时间（TTFR）等。

## 例子

- **章节作用：** 下面的例子演示了你可以如何配置插件以应付不同的场景。

### 如何让 APISIX 作为代理，把用户请求转发给 OpenAI

1. **先准备 OpenAI API Key：** `export OPENAI_API_KEY="<your-api-key>"`。

    - 这个 Key 是 APISIX 调用 OpenAI 时使用的，不是用户调用 APISIX 时使用的。也就是说：用户不需要知道 OpenAI API Key，APISIX 保存并使用 OpenAI API Key。

2. **创建 APISIX Route：**

    ```json
    curl "http://127.0.0.1:9180/apisix/admin/routes" -X PUT \
    -H "X-API-KEY: ${admin_key}" \
    -d '{
        "id": "ai-proxy-route",
        "uri": "/anything",
        "methods": ["POST"],
        "plugins": {
            "ai-proxy": {
                "provider": "openai",
                "auth": {
                    "header": {
                        "Authorization": "Bearer '"$OPENAI_API_KEY"'"
                    }
                },
                "options":{
                    "model": "gpt-4"
                }
            }
        }
    }'
    ```

    - **配置含义：**

        ```text
        Route ID：ai-proxy-route
        外部路径：/anything
        允许方法：POST
        使用插件：ai-proxy
        目标服务商：OpenAI
        OpenAI API Key：从 Authorization 请求头传递
        模型：gpt-4
        ```

3. **客户端请求 APISIX：**

    ```json
    curl "http://127.0.0.1:9080/anything" -X POST \
    -H "Content-Type: application/json" \
    -d '{
        "messages": [
            { "role": "system", "content": "You are a mathematician" },
            { "role": "user", "content": "What is 1+1?" }
        ]
    }'
    ```

### 如何让 APISIX 作为代理，把用户请求转发给 DeepSeek

1. **先准备 DeepSeek API Key：** `export DEEPSEEK_API_KEY="<your-api-key>"`。

    - 这个 Key 是 APISIX 调用 DeepSeek 时使用的，不是用户调用 APISIX 时使用的。也就是说：用户不需要知道 DeepSeek API Key，APISIX 保存并使用 DeepSeek API Key。

2. **创建 APISIX Route：**

    ```bash
    curl "http://127.0.0.1:9180/apisix/admin/routes/deepseek-ai-proxy-route" -X PUT \
        -H "X-API-KEY: ${admin_key}" \
        -H "Content-Type: application/json" \
        -d '{
            "uri": "/deepseek",
            "methods": [
                "POST"
            ],
            "plugins": {
                "ai-proxy": {
                    "provider": "deepseek",
                    "auth": {
                        "header": {
                            "Authorization": "Bearer '"$DEEPSEEK_API_KEY"'"
                        }
                    },
                    "options": {
                        "model": "deepseek-chat"
                    }
                }
            }
        }'
    ```

    - **配置含义：**

        ```text
        Route ID：deepseek-ai-proxy-route
        外部路径：/deepseek
        允许方法：POST
        使用插件：ai-proxy
        目标服务商：DeepSeek
        DeepSeek API Key：从 Authorization 请求头传递
        模型：deepseek-chat
        ```

3. **客户端请求 APISIX：**

    ```bash
    curl "http://127.0.0.1:9080/deepseek" -X POST \
        -H "Content-Type: application/json" \
        -d '{
            "messages": [
                {
                    "role": "system",
                    "content": "You are an AI assistant that helps people find information."
                },
                {
                    "role": "user",
                    "content": "Write me a 50-word introduction for Apache APISIX."
                }
            ]
        }'
    ```

### 根据请求体参数将请求代理到指定模型

> 这一章演示：在同一个 URI 上，根据用户请求体中的 `model` 参数，将请求代理到不同的模型服务。

- **统一入口：** OpenAI 和 DeepSeek 都使用 `POST /anything`。

- **选择依据：** APISIX 使用 `post_arg.model` 读取请求体中的 `model` 字段。

- **路由匹配：**
	- `model = openai`：匹配 OpenAI Route。
	- `model = deepseek`：匹配 DeepSeek Route。

1. **准备模型服务 API Key：**

	```bash
	export OPENAI_API_KEY="<your-api-key>"
	export DEEPSEEK_API_KEY="<your-api-key>"
	```

	- 这两个 Key 由 APISIX 保存并用于调用上游模型服务，用户请求 APISIX 时不需要携带它们。

2. **创建 OpenAI Route：**

	该 Route 的 URI 是 `/anything`，只有当请求体中的 `model` 等于 `openai` 时才匹配。

	```bash
	curl "http://127.0.0.1:9180/apisix/admin/routes/ai-proxy-openai-route" -X PUT \
		-H "X-API-KEY: ${admin_key}" \
		-H "Content-Type: application/json" \
		-d '{
			"uri": "/anything",
			"methods": [
				"POST"
			],
			"vars": [
				[
					"post_arg.model",
					"==",
					"openai"
				]
			],
			"plugins": {
				"ai-proxy": {
					"provider": "openai",
					"auth": {
						"header": {
							"Authorization": "Bearer '"$OPENAI_API_KEY"'"
						}
					},
					"options": {
						"model": "gpt-4"
					}
				}
			}
		}'
	```

	- **配置含义：**
		- Route ID：`ai-proxy-openai-route`。
		- 外部路径：`/anything`。
		- 匹配条件：`post_arg.model == openai`。
		- 目标服务商：OpenAI。
		- 上游模型：`gpt-4`。

3. **创建 DeepSeek Route：**

	该 Route 与 OpenAI Route 使用相同的 URI，但只有当请求体中的 `model` 等于 `deepseek` 时才匹配。

	```bash
	curl "http://127.0.0.1:9180/apisix/admin/routes/ai-proxy-deepseek-route" -X PUT \
		-H "X-API-KEY: ${admin_key}" \
		-H "Content-Type: application/json" \
		-d '{
			"uri": "/anything",
			"methods": [
				"POST"
			],
			"vars": [
				[
					"post_arg.model",
					"==",
					"deepseek"
				]
			],
			"plugins": {
				"ai-proxy": {
					"provider": "deepseek",
					"auth": {
						"header": {
							"Authorization": "Bearer '"$DEEPSEEK_API_KEY"'"
						}
					},
					"options": {
						"model": "deepseek-chat"
					}
				}
			}
		}'
	```

	- **配置含义：**
		- Route ID：`ai-proxy-deepseek-route`。
		- 外部路径：`/anything`。
		- 匹配条件：`post_arg.model == deepseek`。
		- 目标服务商：DeepSeek。
		- 上游模型：`deepseek-chat`。

4. **请求 OpenAI 模型：**

	请求体中的 `model` 设置为 `openai`，APISIX 会匹配 OpenAI Route，并将请求转发给 OpenAI 的 `gpt-4`。

	```bash
	curl "http://127.0.0.1:9080/anything" -X POST \
		-H "Content-Type: application/json" \
		-d '{
			"model": "openai",
			"messages": [
				{
					"role": "system",
					"content": "You are a mathematician"
				},
				{
					"role": "user",
					"content": "What is 1+1?"
				}
			]
		}'
	```

5. **请求 DeepSeek 模型：**

	请求体中的 `model` 设置为 `deepseek`，APISIX 会匹配 DeepSeek Route，并将请求转发给 DeepSeek 的 `deepseek-chat`。

	```bash
	curl "http://127.0.0.1:9080/anything" -X POST \
		-H "Content-Type: application/json" \
		-d '{
			"model": "deepseek",
			"messages": [
				{
					"role": "system",
					"content": "You are a mathematician"
				},
				{
					"role": "user",
					"content": "What is 1+1?"
				}
			]
		}'
	```

### 将 LLM 请求日志发送到 ClickHouse

- `ai-proxy` 负责产生 LLM 请求相关的日志信息，`clickhouse-logger` 负责将 APISIX 的请求日志批量写入 ClickHouse 表。

- **日志内容：**

    - `ai-proxy.logging.summaries`：开启模型、耗时、请求 Token 和响应 Token 等摘要信息的记录。

    - `ai-proxy.logging.payloads`：开启 LLM 请求和响应 payload 的记录。

- **前置条件：**

	- ClickHouse 已启动，并通过 HTTP 接口监听 `8123` 端口。

    - APISIX 可以访问 ClickHouse 的 HTTP 地址，例如 `http://127.0.0.1:8123`。

    - ClickHouse 中创建日志表，字段与 APISIX `clickhouse-logger` 默认日志结构对应：

		```bash
		curl "http://127.0.0.1:8123" -X POST \
			--user "default:" \
			--data-binary @- <<'SQL'
		CREATE TABLE default.llm_logs (
			host String,
			client_ip String,
			route_id String,
			service_id String,
			start_time String,
			latency String,
			upstream_latency String,
			apisix_latency String,
			consumer String,
			request String,
			response String,
			server String
		)
		ENGINE = MergeTree()
		PRIMARY KEY (start_time)
		ORDER BY (start_time);
		SQL
	```

	- **创建带日志插件的 Route：**

	- `include_req_body` 和 `include_resp_body` 确保请求体和响应体写入日志。

    - `endpoint_addrs` 是 ClickHouse HTTP 地址；APISIX 3.13 使用该字段，不能照搬其他版本中的字段名。

	```bash
	curl "http://127.0.0.1:9180/apisix/admin/routes/ai-proxy-clickhouse-route" -X PUT \
		-H "X-API-KEY: ${admin_key}" \
		-H "Content-Type: application/json" \
		-d '{
			"uri": "/llm/logging",
			"methods": [
				"POST"
			],
			"plugins": {
				"ai-proxy": {
					"provider": "openai",
					"auth": {
						"header": {
							"Authorization": "Bearer '"$OPENAI_API_KEY"'"
						}
					},
					"options": {
						"model": "gpt-4"
					},
					"logging": {
						"summaries": true,
						"payloads": true
					}
				},
				"clickhouse-logger": {
					"user": "default",
					"password": "",
					"database": "default",
					"logtable": "llm_logs",
					"endpoint_addrs": [
						"http://127.0.0.1:8123"
					],
					"include_req_body": true,
					"include_resp_body": true
				}
			}
		}'
	```

- **发送 LLM 请求：**

	```bash
	curl "http://127.0.0.1:9080/llm/logging" -X POST \
		-H "Content-Type: application/json" \
		-d '{
			"messages": [
				{
					"role": "system",
					"content": "You are an AI assistant that helps people find information."
				},
				{
					"role": "user",
					"content": "Write me a 50-word introduction for Apache APISIX."
				}
			]
		}'
	```

- **查询日志：**

	请求完成后，`clickhouse-logger` 会将日志批量写入 ClickHouse。可以查询最新的请求记录：

	```bash
	echo 'SELECT * FROM default.llm_logs ORDER BY start_time DESC LIMIT 10 FORMAT Pretty' |
		curl "http://127.0.0.1:8123/" -X POST --data-binary @-
	```

- **日志链路：**

	```text
	客户端
	    ↓ POST /llm/logging
	APISIX Route
	    ↓
	ai-proxy：调用 OpenAI，并生成 LLM 日志信息
	    ↓
	OpenAI
	    ↓ 响应返回 APISIX
	clickhouse-logger：整理请求、响应和耗时信息
	    ↓ 批量写入
	ClickHouse.default.llm_logs
	```

### 将 LLM 信息写入 APISIX 访问日志

> 这一章单独说明如何把 LLM 请求信息写入 APISIX 的 access log，用于分析请求耗时、Token 用量和上游响应情况。

- **LLM 变量：**

	- `request_llm_model`：请求中指定的 LLM 模型名称。
	- `request_type`：请求类型，可能是 `traditional_http`、`ai_chat` 或 `ai_stream`。
	- `llm_time_to_first_token`：从发送请求到收到 LLM 返回第一个 Token 的耗时，单位为毫秒。
	- `llm_model`：实际使用的 LLM 模型。
	- `llm_prompt_tokens`：提示词使用的 Token 数量。
	- `llm_completion_tokens`：补全内容使用的 Token 数量。

- **上游变量：**

	当 `ai-proxy` 在 APISIX 内部通过 cosocket（协程 Socket）自己连接并调用 LLM 服务时，下面这些上游变量会自动填充：

	- `upstream_addr`：上游 LLM 服务地址，例如 `api.openai.com:443`。
	- `upstream_status`：上游 LLM 服务返回的 HTTP 状态码。
	- `upstream_response_time`：接收上游完整响应的耗时，单位为秒，例如 `2.858`。
	- `upstream_connect_time`：与上游 LLM 服务建立连接的耗时，单位为秒。
	- `upstream_header_time`：接收上游响应头的耗时，单位为秒。
	- `upstream_response_length`：上游响应体的总字节数，例如 `1024`。
	- `upstream_host`：endpoint 中配置的上游主机名，例如 `api.openai.com`。
	- `upstream_scheme`：连接上游时使用的协议，例如 `https`。
	- `upstream_uri`：发送给上游的请求 URI 路径，例如 `/v1/chat/completions`。

- **配置访问日志格式：**

	在 APISIX 配置文件中增加这些变量。官方示例使用 `conf/config.yaml`；实际部署时应修改 APISIX 容器挂载的配置文件：

	```yaml
	nginx_config:
	  http:
	    access_log_format: "$remote_addr - $remote_user [$time_local] $http_host \"$request_line\" $status $body_bytes_sent $request_time \"$http_referer\" \"$http_user_agent\" $upstream_addr $upstream_status $upstream_response_time \"$upstream_scheme://$upstream_host$upstream_uri\" \"$apisix_request_id\" \"$request_type\" \"$llm_time_to_first_token\" \"$llm_model\" \"$request_llm_model\" \"$llm_prompt_tokens\" \"$llm_completion_tokens\""
	```

- **使配置生效：**

	修改配置文件后，需要重新加载 APISIX。仅修改文件而不 reload，正在运行的网关不会使用新的访问日志格式。

- **响应示例：**

	发送请求后，LLM 响应中的 `usage` 会提供 Token 用量，例如：

	```json
	{
	  "model": "gpt-4-0613",
	  "choices": [
	    {
	      "index": 0,
	      "message": {
	        "role": "assistant",
	        "content": "1+1 equals 2."
	      },
	      "finish_reason": "stop"
	    }
	  ],
	  "usage": {
	    "prompt_tokens": 23,
	    "completion_tokens": 8,
	    "total_tokens": 31
	  }
	}
	```

- **访问日志示例：**

	```text
	192.168.215.1 - - [21/Mar/2025:04:28:03 +0000] api.openai.com "POST /anything HTTP/1.1" 200 804 2.858 "-" "curl/8.6.0" api.openai.com:443 200 2.858 "https://api.openai.com/v1/chat/completions" "5c5e0b95f8d303cb81e4dc456a4b12d9" "ai_chat" "2858" "gpt-4" "gpt-4" "23" "8"
	```

- **日志字段解析：**

	- 上游地址：`api.openai.com:443`。
	- 上游状态码：`200`。
	- 请求类型：`ai_chat`。
	- 上游响应耗时：`2.858` 秒。
	- 首 Token 返回耗时：`2858` 毫秒。
	- 请求指定模型：`gpt-4`。
	- 实际使用模型：`gpt-4`。
	- 提示词 Token 数量：`23`。
	- 补全 Token 数量：`8`。
